Part 1

The problem, in plain words

Why this problem statement exists at all.

India has many government companies (CPSEs): Oil India, NTPC, IOCL, CPCL, ONGC, BPCL, GAIL and others. Each one keeps its own list of every item it buys and stocks: pipes, valves, bearings, bolts, cables. This list is called the material master. Every item in it gets a material code.

The trouble is that every company writes the same item differently and gives it a different code. Often the same company has the same item two or three times, because different storekeepers typed it differently over the years.

One gasket, four companies, four codes (from our test data)

CompanyTheir codeHow they wrote itUnit
BPCLBR-01454GASKET SPIRAL WOUND SS304 4IN 150#EA
ONGC5001164GASKET 4 IN SS304 SPIRAL WOUND 150# GRAPHITE FILLERPCS
GAILG/001372GASKET,SS304,SPIRAL WOUND,4 IN,FLX/SW/304/4EACH
IOCLMAT-01276GASKET, SPIRAL WOUND, SS304, FLEXITALLIC, SW-034-4-150NO

It is the same gasket. Even the unit is spelled four ways: EA, PCS, EACH, NO.

What this costs

  • Extra stock. The same item sits in the store under two codes, so both get bought.
  • No buying together. Companies cannot combine orders for a better price, because nobody can see it is the same item.
  • No price comparison. One company may pay far more than another for the same thing.
  • Painful system changes. Moving to a new SAP system means carrying all the mess across.

Our job

Read every company's list. Work out which lines describe the same physical item. Give that item one National Material Code. Keep a link from the national code back to every company's own code. Change or delete nothing inside any company's system.

Why are descriptions so messy? Several reasons together: the SAP description field is only 40 characters, old systems had even shorter fields, and there was never a firm rule on how to write an item, so every storekeeper made up their own short forms. Always say "several reasons". Never blame only SAP.

Part 2

The one big idea

This is the heart of the project and the centre of the demo.

The normal way to find duplicates is to compare the words: if two lines look alike, they are probably the same. We measured this on our own system, and it fails in both directions.

CPCLSKF 6205-2RS DEEP GROOVE BALL BEARING
IOCLFAG 6205-2RSR BEARING, 25X52X15MM, SEALED
Same bearing Text looks only 0.833 similar. Different maker, different words. But 6205 is a world standard size, so both are 25 × 52 × 15 mm.
Company AGASKET SPIRAL WOUND SS316 4IN 150#
Company BGASKET SPIRAL WOUND SS304 4IN 150#
Different items Text looks 0.989 similar, almost identical. But SS316 and SS304 are different steels. Swapping them in acid service can make a line fail.

The problem with words

The pair that must never merge (0.989) looks more alike than the pair that should merge (0.833). No cut-off number can fix this. Any setting that accepts the bearings also accepts the dangerous gaskets.

So we stopped comparing spelling and started comparing specifications.

StepWhat we do
1. ReadPull out the facts from each line: type, size, grade, pressure class, standard number.
2. VetoIf a critical fact is different (grade, pressure, size), stop. It is a different item, however similar the words.
3. ScoreIf nothing is vetoed, score how well the facts agree. Brand is ignored on purpose, which is how SKF and FAG meet.

Result today: the two bearings match at 0.971. The two gaskets are blocked on grade.

A simple way to picture it

To check if two forms belong to the same person, you don't compare how they spelled their name ("Madhu", "Madu", "M. Chanda"). You compare their date of birth and Aadhaar number. Specs are the date of birth of an item.

"If we train no model, how is this AI?"

AI is used where it is strong: an AI model reads messy text and turns it into facts, and embeddings find records that might be the same. Fixed rules make the final decision, because a refinery needs a decision that can be explained and gives the same answer every time. We train no model because no labelled CPSE examples exist anywhere to train on. AI reads. Engineering decides. Governance records.

Part 5

Two jobs, one engine

The same matching engine is used in two ways.

Job 1 · Harmonise (clean up the past)

In: a company's whole material master, thousands of lines.

Out: a national code for every item, and a table linking every old code to it.

Runs once per company, then again when new data arrives.

Job 2 · Gate (protect the future)

In: one new-code request from a storekeeper.

Out: one of four answers before a new code is created.

Without this, the mess comes back within a year.

The four answers of the Creation Gate Built

AnswerMeaningExample from our demo
EXISTSThis item already has a code. Use that one.FAG 6205-2RSR BEARING, 25X52X15MM, SEALED
REVIEWClose to an existing item. A human should look.—
NEWTruly new. Create a code, and show the near items it was told apart from.GASKET SPIRAL WOUND SS321 4IN 150#
INCOMPLETENot enough written to decide. Names the missing facts.BEARING

Another demo case: a pressure gauge for 0–16 BAR is correctly called NEW, because the stored gauge reads 0–10 BAR. Same words, different range.

Why the INCOMPLETE answer matters

A storekeeper who types only "BEARING" gets told exactly what to add (the bearing number, or bore, outside size and width). The problem statement asks for "faster specification finalisation". This is it.

Part 7

The workflow, step by step

We follow one real pair through every step: CPCL's SKF bearing and IOCL's FAG bearing.

CPCL · code 100001445SKF 6205-2RS DEEP GROOVE BALL BEARING
IOCL · code MAT-01248FAG 6205-2RSR BEARING, 25X52X15MM, SEALED
00Ingest: take the data inPartly

Each company uploads its list as a spreadsheet, shaped like a SAP export. Or a storekeeper sends one new-code request. The original line is kept exactly as it was.

Our pair: both lines come in with their company and code attached.

Still to build: append-only, versioned storage, so nothing is ever overwritten.

01Normalise: clean the textPartly

Expand short forms (M.S. → mild steel, BRG → bearing). Fold unit spellings (EA, NOS, PCS, EACH, NO → one unit). Treat C.S., CS and C S as the same.

Our pair: "DEEP GRV" and "DEEP GROOVE" become the same words.

Still to build: real Indian short forms (BLK, SMLS, GLV, ERW, SCIM); sizes as names (1/2" = DN15 = 15NB); fractions (3/4" is not 4"); standards written different ways (ASTM-F439 = ASTM F439); pack sizes kept apart from units.

02Classify: what kind of item is it?Partly

Decide the category. Each category has its own list of facts that matter.

Our pair: both are bearing, so the facts that matter are bearing number, bore, outside size, width and seal.

Built: 9 categories (bearing, gasket, pipe, valve, fastener, flange, rotating, instrument, electrical). Still to build: cable, fitting, plate, tube; and if the system is unsure (below 70%), it queues the record for a human instead of guessing.

03Extract: read the specsPartly

Pull out each fact with a confidence score. Rules go first. The AI model is used only when a critical fact comes out below 70% confidence. Results are saved, so the AI is never called twice for the same record.

Our pair: CPCL → bearing number 6205, seal 2RS, brand SKF. IOCL → 6205, 25 × 52 × 15 mm, sealed, brand FAG.

Problem: works on our test data, but on real text only 21 of 902 lines give two or more facts. Still to build: the fix, plus an "evidence span" for every fact (which exact words it came from).

04Derive: fill gaps from standards★ Ours aloneNot yet

Engineering standards tell us facts nobody typed. A bearing numbered 6205 is always 25 × 52 × 15 mm (ISO 15). A pipe size plus schedule gives its wall thickness (ASME B36.10). A flange class gives its rating (ASME B16.5).

It also knows when two standards mean the same thing. IS 1367 (Part 3) is identical to ISO 898-1, because BIS adopted it word for word. ASTM F3125 Grade A325 is only close to them. And it knows withdrawn standards: ASTM A325 was withdrawn in 2016 and now lives on as ASTM F3125 Grade A325, so old records still meet new ones.

Our pair: CPCL never typed the size. The standard adds 25 × 52 × 15 mm, marked "derived, confidence 0.85". Now both records have the same sizes.
05Self-check: does the record agree with itself?★ Ours aloneNot yet

Before comparing with anything else, check the record against itself. If a line says 6205 but also 30X62X16, one of them is wrong. That record is kept out of automatic merging and sent to a human. Bad data must not become national data.

Our pair: IOCL says 6205 and 25 × 52 × 15. The standard agrees. Pass.
06Block: pick only the pairs worth comparingNot yet

Comparing everything with everything is impossible at scale: 15,000 records make 112 million pairs. So we only compare records with the same category and the same key facts (like the same bearing number or the same pipe size), plus close neighbours by embedding.

Each pair also gets a scope: same plant, same company across plants, or across companies. Scope decides who reviews it.

Our pair: both are bearing + 6205, so they are put side by side. Scope: across companies (CPCL and IOCL).

Today: all pairs are compared, which is fine at 100 records and fails at 15,000. This is task 2 on the build list.

07Veto: stop on any critical differenceBuilt

Runs before any score. Each critical fact is MATCH, MISMATCH or UNKNOWN. One MISMATCH on grade, pressure, size or type blocks the pair, whatever the words say. UNKNOWN (one side is silent) is not counted as agreement or as conflict. A price gap of more than 10× also blocks: a ₹42 bolt and a ₹4,200 bolt are not the same item.

Our pair: bearing number MATCH, bore MATCH, seal MATCH. No veto.

Still to add: service ratings (sour service NACE MR0175, IBR, cryogenic, fire-safe). If only one side has it, the pair is never "identical". It becomes a one-way substitute that a human decides.

08Score: how well do they agree?Built

Three signals. Specs carry the most weight. Text counts a little. Buying history (same vendor, similar price) can only confirm or block, never add points. Brand and maker part number are ignored. If too few critical facts are known, the score is capped below auto-merge.

Our pair: score 0.971.

Still to add: ★ the counterfactual for every blocked or near pair ("if the grade matched, this would score 0.94"), and an exact match on the standard number first (6205 = 6205, whatever the maker's part number).

09Relate: what kind of match is it?Not yet

Not just "same" or "not same". Five answers: identical · equivalent (different standard, same item) · substitute (one can replace the other, one way only, always a human decision) · variant of (same family, other size: 6204 · 6205 · 6206) · incompatible.

Our pair: IDENTICAL.
10Route: auto, review or blockedBuilt

Score 0.90 or more → auto-merge. Between 0.70 and 0.90 → human review. A veto fired → blocked. The reviewer screen supports keyboard shortcuts (A approve, R reject, S skip), with all the evidence on one screen.

Our pair: 0.971 → auto-merge.

Still to add: safety-critical items always go to a human; the review queue sorted by risk × money × safety; and some random audit cards taken from the already auto-merged pairs, so humans keep checking the machine's own "sure" answers.

11Canonicalise: one item, one national codeBuilt

First, join the matched pairs into groups, one group per real item. Every pair inside a group must still look alike. If one doesn't, the whole group goes to a human for review, and so does any group larger than 25. Then build one clean golden record, write a standard description, attach the UNSPSC class (a world product catalogue), and issue the code NMC-<class>-<serial>.

Our pair: ends up in one group of 9 bearing records from 5 companies → NMC-31171500-000001 · BEARING, DEEP GROOVE BALL, 6205, 25X52X15 MM, 2RS SEALED · UNSPSC Bearings.

Still to add: a fixed order for settling disagreements between records (standard first, then highest confidence, then majority, then latest purchase, then most precise), and if a critical fact is still disputed, no code is issued.

12Govern: record who did what★ Ours aloneNot yet

An audit log that can only be added to: who, what, when, why, and how to reverse it. Five actions: ACCEPT · REJECT · MARK_DIFFERENT (and say which field) · UNMAP · DISPUTE. The approval model is explained in Part 8.

Important: this is problem-statement capability 7 (audit trail), and it is the one capability with nothing built today.

13Outputs: what people getPartly

Built: creation gate · savings report (buying together) · safety report (merges we refused, and why) · units report · national code and mapping table · eight-screen demo.

Still to build: staged migration pack for a company's SAP team · data-quality scorecard · SAP-shaped export · counters for duplicates prevented and specs completed.

Part 8

How one national code works for every company

The question everybody asks: "each company has its own system, so how does one code reach all of them?"

  1. Oil India uploads its material list. The system reads it and first finds duplicates inside Oil India (across its own plants). This alone is useful from day one.
  2. NTPC uploads its list. The same happens inside NTPC.
  3. The system compares across both companies. It finds items that are the same in both, for example the same line pipe.
  4. The national registrar issues one national code for that item. In our test data, one SS304 gasket became NMC-31400000-000001, linked to four companies' codes (the table in Part 1).
  5. A mapping table links it to each company's own code. Oil India's code and NTPC's code both point to the same national code.
  6. Nothing changes inside either company's SAP. They keep using their own codes. The national code sits on top.
  7. If NTPC thinks the link is wrong, it raises a dispute. The pair goes back to a human, and the objection is written in the audit log.

Think of UPI

Your UPI ID sits on top of your bank account. The bank does not change your account number. UPI did not ask every bank to approve every link. The national code works the same way: it links, it does not edit.

The approval rule: consent scales with harm

ActionWho decidesWhy
Link two codes under one national codeThe national registrar. No company can veto.A link changes nothing inside a company and can be undone.
Retire or switch off a codeOnly the company that owns it. Nobody else, ever.This changes a company's own system, so only it may decide.
Show prices or vendors across companiesNever shown raw. Only price bands and hidden vendor IDs, and hidden entirely if fewer than 3 companies buy the item.With only two companies, "the best price" gives away the other's price.
Dispute a linkAny affected company, at any time.A right to dispute, not a right to veto.

Why we dropped "both companies must approve"

If every link needs two busy people in two companies to click "approve", nothing ever gets issued. The reviewer gets only extra work, while procurement gets the savings. One company staying silent would block a code forever. Our new rule lets the registry keep moving and stops it when there is evidence. It also gives companies more power than a plain central registry, where they would have no say at all.

Two phases

Phase 1 · inside one companyDuplicates across one company's own plants. No data sharing, no agreement between companies, no policy change. Value on day one.
Phase 2 · across companiesPrice bands and hidden vendor IDs, never raw prices or names. A company learns a better price exists, never who got it.

Part 9

The rules we never break

Every design choice in this project comes back to one of these.

RuleIn plain words
Precision over recallMissing a duplicate costs a little money. A wrong merge can put the wrong valve in a refinery line. When unsure, ask a human.
Nothing is destroyedData is only ever added. Every original code is kept. Undoing a merge only removes a link.
Every merge is explainableFor any merge we can show which facts matched, what the scores were, and which words they came from.
The AI never decidesThe AI reads text into facts. Fixed rules decide. One AI call per record, never per pair.
Veto before scoreA critical difference stops everything. "Unknown" never counts as agreement or as conflict.
Thresholds change only by a recorded commitThe system never tunes itself. A person changes a setting and it is recorded.
The answer key is for testing onlyThe matching code never sees the correct answers. A matcher that has seen them has a worthless score.
No number without a runNo number goes on a slide unless it came from a recorded test run.
Consent scales with harmLinking needs no permission. Only the owner retires a code. Anyone can dispute.
No live AI in the demoEverything is computed before. The demo runs the same every time, with no internet.

Part 11

The real data: what we found

Our biggest weakness was "only tested on data we made". This is how we are fixing it.

First, the hard truth

Why the AI can't label the proof set

If whoever builds the extractor also writes its answer key, the test only measures the builder agreeing with themselves. A judge would ask "who checked your AI's work?" Two people labelling blind is the answer to that question.

  1. Each person opens only their own sheet (data/real/labels/isha.csv or meghna.csv).
  2. keep: y one real item (even if under-specified) · n not an item (works, clause, vendor, a range like "up to 1.1 kV") · m several different items in one line · ? unsure.
  3. category: one of the 13, or other. group: the same tag (G1, G2, …) on lines that are the same item.
  4. Run python src/labels.py compare. It prints the agreement and lists every disagreement. Decide each one together and write down why.
  5. Run python src/labels.py finalise. That writes the real answer key.

What the dev half already shows

  • 64% of lines are real items, 14% join several items, 22% aren't items at all.
  • 36% of real items fall outside our 13 categories (drilling equipment, batteries, wire rope, pumps). The "other" path must still find their duplicates, sending them only to review.
  • 32 same-item groups. Example: Line Pipe, 4", Seamless, B/E, 12.66 PPF = Line Pipe 101.60 mm Seamless, B/E, 12.66 PPF. 101.6 mm could be "4 inch" converted naively or the real width of a 3½-inch pipe. Only the weight (12.66 lb/ft) proves it's 4-inch.
  • Today's extractor names the category for 87% of items but reads two or more facts from only 3%. Pipes: 0 of 77.

How to talk about these numbers

Precision 1.00 on data we made ourselves means "we undid 100% of the mistakes we put in". A sharp judge will say so. That is why the real-data numbers go beside the test numbers, even when they are lower. A smaller real number is more believable, and showing it builds trust.

What we can and cannot say

We can say

  • Decisions are repeatable and explainable
  • Standards-aware across makers and writing styles
  • Duplicates stopped at creation, not only cleaned
  • Works inside one company on day one
  • Much less data exposure across companies
  • Tested on real Oil India and NTPC text too, both reported
  • Nothing trained, so nothing to retrain

We must never say

  • 100% precision, or one blended number
  • Production or live accuracy
  • Live SAP integration
  • "Secure", "private", "encrypted"
  • That the real data is a material master
  • That we invented entity resolution
  • Any stock or inventory reduction figure

Part 15

Words you will hear

Short meanings for every technical word in this project.

CPSECentral Public Sector Enterprise: a government company (Oil India, NTPC, IOCL, CPCL…).
Material masterA company's list of every item it buys and stocks.
National Material Code (NMC)The one code we give each real item, e.g. NMC-31171500-000001.
Mapping tableThe table that links each national code to each company's own code.
Specification / attributeA fact about an item: size, grade, pressure class, standard number.
ExtractionReading a messy line and pulling out its facts.
EmbeddingText turned into a list of numbers, so similar lines sit close together. Used only to find candidates.
BlockingComparing only records that could possibly match, instead of every pair.
Veto / hard blockerA critical fact that, if different, stops a match immediately.
Grouping (union-find)Joining matched pairs into groups: if A = B and B = C, then A, B and C are one item, but only if A and C also still look alike.
Golden recordThe one clean, best record made from all the duplicates of an item.
UNSPSCA world product catalogue with standard class numbers. We use it instead of inventing our own.
NB / DN / NPSNames for pipe sizes. "Name, not measurement": 15NB is a pipe about 21.3 mm across.
Standard (ISO, ASME, IS, ASTM)A published rule book. ISO 15 fixes bearing sizes; ASME B36.10 fixes pipe sizes.
SupersessionWhen a standard is withdrawn and replaced (ASTM A325 → ASTM F3125 Grade A325).
Counterfactual"What would the score be if this one field matched?"
PrecisionOf the merges we made, how many were right. Our most important number.
RecallOf all real duplicates, how many we found.
k-anonymity 3Hide a price comparison if fewer than 3 companies buy the item, so nobody can work out another's price.
Synthetic dataTest data we made ourselves, with a hidden answer key.
Hold-outData kept aside only for testing. Ours is the real Oil India and NTPC lines.
Near-miss trapTwo records that look alike but must never merge (SS304 vs SS316). Used to test safety.
RegistrarThe national body that issues national codes.

If you remember only three things

  1. We match on specifications, not spelling. Words fool you; specs don't.
  2. A national code links, it never edits. Nobody's system changes; anyone can dispute.
  3. Fix real-text reading first. 21 of 902 is the number that decides everything else.
