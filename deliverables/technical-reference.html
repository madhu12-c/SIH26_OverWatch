01The problem

Central Public Sector Enterprises operating in oil and gas, power, steel, mining and heavy engineering each maintain an independent material master — the catalogue of every pipe, valve, bearing, gasket and fastener the organisation buys and stocks. The same physical item is assigned a different material code, a different description, a different unit of measurement and a different classification in each enterprise, and is frequently duplicated within a single enterprise as well.

The problem statement names six consequences. Each is addressed by a specific part of the system described in this document.

Stated in the problem statementAddressed by
Duplication of material mastersBlocking, scoring and clustering → one national code per physical item
Inconsistent descriptionsCanonicaliser → noun-modifier standard description

Why the descriptions diverge

Three causes compound, and the third is the largest. Attributing the problem to any single one of them is inaccurate.

  1. Field length in the ERP. In SAP, material descriptions are stored in table MAKT, field MAKTX, which holds a maximum of 40 characters. MAKT is the text table of MARA; the description field does not exist in MARA itself. Forty characters is not enough for a complete specification, so cataloguers abbreviate.
  2. Migration from older systems. Data loaded into current ERP instances arrived from predecessor systems with even shorter description fields, and the truncation is preserved.
  3. No enforced cataloguing standard. Where no naming convention is mandated and audited, each storekeeper develops a private shorthand. This is the dominant cause, and it is the reason the same item diverges even within one enterprise on one ERP.
Verified MAKT-MAKTX is defined as a 40-character material description field, and MAKT is the text table for MARA. Confirmed against the published SAP data dictionary.

02Sources of material data

Material master data does not exist as a public dataset. It sits inside each enterprise's ERP. Four public sources establish what real material records look like, what attributes procurement actually distinguishes on, and which classification standard to adopt. Each was checked directly.

Government e Marketplace — gem.gov.in

GeM is the Government of India's national public procurement portal, used by central and state ministries, departments, PSUs and autonomous bodies. It publishes over 10,000 product categories, including the engineering categories this system covers — pumps, valves, pipes and fittings, engineering tools and safety equipment. Category listings carry structured technical parameters, and the marketplace hosts buyer-uploaded technical specification documents for items such as API 6D valves, control valves, HDPE pipes and pipeline ball valves.

Domain concept adopted from GeM GeM defines Golden Parameters as those specifications which have maximum impact on the technical aspects of a product, may directly or indirectly impact its cost, and enable a buyer to choose the appropriate product. This is precisely the distinction this system encodes as hard blocker fields in Section 07 — the attributes on which a mismatch makes two items non-interchangeable regardless of how similar everything else is. The concept is not invented here; it is already the operating vocabulary of Indian public procurement.

Central Public Procurement Portal — eprocure.gov.in

CPPP is the portal through which all central government organisations publish tender enquiries, corrigenda and award-of-contract details. Financial bids are submitted on a standardised Bill of Quantities spreadsheet whose template structure may not be altered. Published BOQ line items are the closest public analogue to a material master row: a free-text item description, a unit of measurement and a quantity, written by a procurement officer under the same abbreviation pressures described in Section 01. BOQ item text is therefore the reference for how real description variation actually looks, rather than how it might be imagined to look.

UNSPSC — classification standard

The United Nations Standard Products and Services Code is a four-level hierarchy — segment, family, class, commodity. The system classifies to class level and embeds the class in every national code it issues. Using an international standard rather than a locally invented taxonomy matters for a national system: no CPSE is asked to adopt a scheme created for this project, and the resulting codes remain interoperable with any procurement system that already speaks UNSPSC. Every class used is listed and verified in Section 09.

SAP MM data model

The material master tables define the shape of what an enterprise would export. MARA holds general material data keyed by MATNR; MAKT holds descriptions per language, keyed by MATNR and SPRAS, with MAKTX as the 40-character short text. MARC holds plant-level data and MBEW valuation. The ingestion format mirrors this structure so an export from a live system requires no reshaping.

03The central technical problem

This is entity resolution over short, heavily abbreviated, domain-specific text, with no labelled training data, where a match means functional equivalence rather than textual similarity, at a scale that forbids all-pairs comparison.

Property of the dataConsequence for the design
Descriptions are 8–15 wordsWeak signal; text alone is insufficient
Heavy abbreviation — M.S., SS316, SCH40, NBOut-of-vocabulary; a normalisation layer is required
No training labels existUnsupervised methods only
Equivalence is functional, not textualTwo records can be interchangeable while sharing almost no words
Masters run to millions of rowsBlocking is mandatory; all-pairs comparison is excluded
Error costs are asymmetricA wrong merge is far more costly than a missed duplicate

The design consequence The pair that must never merge scores higher than the pair that should. The ordering is inverted, and an inverted ordering cannot be corrected by moving a threshold: at 0.80 both merge, at 0.90 the bearing is missed and the gasket still merges, at 0.99 both fail. No setting produces the correct outcome for both. The system therefore does not tune the threshold — it changes what is measured, and matches on extracted specifications rather than on text.

04System architecture

Nine stages run in sequence. Each writes a file that the next stage reads, so any stage can be re-run independently and every intermediate result is inspectable. Data is separated into three folders under a strict rule: inputs are read-only, outputs are regenerable, and the ground-truth answer key is read by evaluation alone and never by any matching component.

Where the language model sits, and where it does not

The model is called once per record, at ingestion, to extract attributes. It is never called on a pair of records and it never decides whether two records match. Matching is deterministic arithmetic over already-extracted attributes. Two properties follow from this and both are requirements rather than optimisations.

  • Auditability. Every merge decision can be replayed and explained from stored numbers. A hallucinated merge is structurally impossible because the model is not in the decision path.
  • Cost and latency. One million records require one million extraction calls, executed once and stored. Calling a model per candidate pair would require tens of millions of calls on every run.

05Normalisation and unit harmonisation

The problem statement names units of measurement explicitly in its background. UoM divergence is handled as a first-class concern rather than as a side effect of text cleaning, because a unit mismatch silently corrupts price comparison: a price per piece and a price per box of one hundred are not comparable, and nothing in the description says which is which.

The evaluation set contains ten distinct unit strings representing three real units.

Normalisation also expands domain abbreviations before extraction runs. Dotted forms are the difficult case: once punctuation is stripped, C.S. becomes c s and no longer matches a dictionary entry for cs, so the normaliser tests both the spaced and the compacted form of every candidate. Dimensional forms vary independently of the words around them — 25X52X15MM, 25 x 52 x 15 mm and 25*52*15 M.M. are the same measurement — and are rewritten to a single form before any comparison.

Derived values carry lower confidence

The bearing pair in Section 03 illustrates the mechanism. One record states 25X52X15MM; the other states only 6205. Because 6205 is an ISO designation with fixed dimensions, the extractor returns bore 25, outer diameter 52 and width 15 for both records — but marks them at lower confidence on the record where they were derived from the designation rather than read from the text. The distinction is preserved so that a reviewer can see which values were inferred.

Extraction is cached and resumable

Results are stored keyed by record identifier, so a re-run extracts only records not already present. A regex fallback handles every category without a model call, which keeps the pipeline operable without network access. On the evaluation set, extraction returned typed specifications for all 100 records.

07Blocking and scoring

Blocking

Comparing every record against every other is quadratic and is excluded at any realistic scale. Candidate pairs are generated by a category gate, a key attribute match and top-k nearest neighbours in vector space. On the evaluation set, 4,376 pairs were eliminated by the category gate alone before any scoring occurred, leaving 292 pairs to score.

Three signals

SignalBasisWeight
SpecificationsField-by-field agreement between extracted attribute setsHighest. Grows with the number of fields actually verified.
Procurement behaviourShared vendor, comparable unit price band, order size, plantSecondary, and independently protective
TextCosine similarity between sentence embeddingsLowest. Never decisive on its own.

Specification weight is adaptive: a pair agreeing on eight verified fields carries more specification weight than a pair agreeing on two, because the evidence is stronger. Text weight falls correspondingly. This prevents the weakest signal from dragging down a pair whose specifications align completely — which is exactly the bearing case, and exactly the outcome the design exists to produce.

The procurement signal is not only additive evidence. It is also a guard against false merges: a bolt priced at ₹42 and a bolt priced at ₹4,200 cannot be the same item however similar their descriptions and specifications appear. A price ratio beyond an order of magnitude blocks the pair outright.

Three rules that matter more than the weights

Hard blockers are veto fields

Material grade, pressure rating and key dimensions are veto fields. A mismatch forces the score to zero regardless of every other signal. This is the engineering property GeM calls a Golden Parameter: the attribute that determines whether one item can physically and safely replace another.

Ignored fields

Brand and vendor part number never contribute to a match. This single rule is what allows an SKF bearing and an FAG bearing carrying the same ISO designation to resolve to one item. Functional equivalence does not depend on who manufactured the part.

Missing is not mismatched

When one record is silent on a field, that is absent information, not evidence of difference, and no penalty is applied. The converse case is handled separately and strictly: if a hard field was never extracted from one side, the pair cannot be auto-merged, because the veto could not be evaluated. Such pairs are capped below the auto-merge threshold and routed to human review.

08Clustering and confidence bands

Scored pairs form a graph. Connected components under union-find produce clusters, but transitive closure introduces a specific hazard: if A matches B and B matches C while A and C do not match, the component still contains all three, and a single bridging record can pull hundreds of unrelated items into one blob.

Three defences are applied.

  • High join threshold — only pairs above the review floor create an edge.
  • Cohesion validation — every intra-cluster pair must score above a minimum. A cluster containing a weakly attached member is split rather than accepted. Two clusters were held back on this rule in the evaluation run.
  • Size cap — clusters beyond a maximum size are routed to review rather than merged automatically.

Human review is the specified design

The problem statement uses the words recommend, propose, review, validate and approve throughout, and lists a user validation and approval workflow among its expected capabilities. The middle band exists because the specification calls for it, not as a hedge against accuracy.

Two governance rules follow. Within a single enterprise, that enterprise's own reviewer decides alone. Across two enterprises, both sides must approve before a national code is issued — no organisation decides the identity of another organisation's material. Merges are reversible: reversing one deletes mapping rows and never deletes source data, because the material table is append-only and original codes are never overwritten.

A classification limit worth stating plainly UNSPSC family 31400000 divides gaskets by manufacturing method — molded (31401500), die cut (31401600), stamped (31401700), water jet cut (31401800) and liquid (31401900). National code

The code carries its classification: NMC-<UNSPSC class>-<serial>. It sits above existing codes and links them, in the way Aadhaar and UPI added a layer without replacing what was underneath. No enterprise changes its own code; a CPCL storekeeper continues to type 100001445.

10Federated operation

Commercial master-data platforms require all participating data to be centralised. No CPSE will transfer its negotiated prices and its vendor list to a shared repository, and this is a governance constraint rather than a missing feature. It is the reason a national material master has not previously existed.

The system is designed so that matching and benchmarking work without commercially sensitive values crossing an organisational boundary.

Benchmark, not attribution

An enterprise learns that a better price exists and how far above it their own price sits. It does not learn which organisation achieved that price. Where fewer than three enterprises appear in a cluster the benchmark is suppressed entirely, because with only two participants the minimum price is the other party's price. Four items were suppressed under this rule on the evaluation set.

Stated precisely This design significantly reduces data exposure. It is not described as cryptographically secure, and that distinction is deliberate: embeddings are partially invertible and hash-based encodings have known attacks. Secure multi-party computation is the correct answer to that stronger requirement.

Scope of these figures

These results are measured on a 100-record evaluation set whose variation was constructed to reproduce the abbreviation, reordering, unit-format and typographic patterns observed in public procurement text. A measurement made against a constructed answer key establishes that the method behaves as designed; it does not by itself establish the figure a live material master would produce. The next measurement to make is against a hand-labelled sample of real records drawn from GeM and CPPP listings, reported alongside these numbers rather than in place of them.

12Design rules

These constraints hold across every component and are not traded away for accuracy.

RuleReason
Precision over recallA missed duplicate costs an opportunity. A wrong merge in a refinery material master can put the wrong part in a line. Thresholds are set conservatively and uncertainty is routed to a person.
Nothing is destroyedThe material table is append-only. Original codes are always retained and mapped. Reversing a merge removes mapping rows and never removes source data.
Every merge is explainableWhich signals fired, what each scored and which fields agreed are stored with the decision, so a reviewer sees the evidence rather than a number.
The model never decides a mergeIt extracts attributes. Matching is deterministic scoring over extracted data, which keeps the system auditable and makes a hallucinated merge structurally impossible.
One model call per recordNever per pair. Per-record cost is linear and paid once; per-pair cost is quadratic and paid on every run.
No enterprise decides for anotherWithin one CPSE, that CPSE's reviewer decides alone. Across two, both must approve before a national code is issued.
The answer key is never read by the matcherGround truth is read by the evaluation harness alone. A matcher that has seen the answer key produces a precision figure that means nothing.

Positioning

Commercial master-data management platforms exist, and record linkage as a field dates to Fellegi and Sunter in 1969. Attribute-based matching is not new. What is claimed here is execution and scope: these platforms deploy inside a single enterprise, whereas this is a cross-enterprise problem whose hard parts are trust, data sharing and the issuance of one national identity; the abbreviation vocabulary is learned from the corpus rather than configured by consultants per client; and national strategic procurement data remains on sovereign infrastructure.
